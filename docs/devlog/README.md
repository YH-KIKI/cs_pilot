# 개발 기록

일차별 기록은 **무엇을 했고 어디까지 확인했는지**, [주요 판단·문제 해결 기록](../decisions.md)은 **왜 선택하거나 바꿨는지**를 남긴다. Git 브랜치·커밋·PR 운영은 [별도 규칙](../git-workflow.md)을 따른다.
핵심 함수의 Python 문법·호출/예외 흐름·직접 풀 수정 과제는 [학습 기록](../learning/README.md)에 따로 두고, 이 일지에는 링크만 남긴다.

## 갱신 방법

- 의미 있는 작업을 마무리할 때 해당 일차 기록을 갱신한다. 같은 일차의 후속 작업은 기존 기록에 이어 쓴다.
- 파일명은 `dayNN-YYYY-MM-DD.md`로 한다. 본문에 작업 날짜와 프로젝트 일차를 함께 적고, 실제 날짜와 일차 귀속 기준이 다르면 명시한다.
- 완료/진행 중, 실제 검사와 결과, 남은 문제/다음 작업, 관련 커밋·PR을 짧게 남긴다. 예정된 작업을 완료 항목에 넣지 않는다.
- 과거 검사 결과는 당시 기록임을 표시한다. 현재 문서 수정에서 재실행하지 않았다면 구분한다. 실패·미실행 항목과 이유도 남긴다.
- 결정·오류의 자세한 원인과 대안은 decisions.md 항목으로 연결한다. 로그에는 결과와 다음 행동만 요약한다.
- 커밋·PR이 생기면 실제 해시·링크를 연결한다. 로컬에만 있는 커밋은 해시와 로컬 조회 명령을 적고, 아직 접근할 수 없는 원격 링크는 만들지 않는다.
- 특별한 작업이 없는 날은 파일을 만들지 않는다. 2일차 이후 파일과 빈 성과표를 미리 생성하지 않는다.

필요한 항목만 사용한다: 날짜/일차 → 완료·진행 중 → 검증 → 남은 문제·다음 작업 → 커밋·PR/관련 판단.
