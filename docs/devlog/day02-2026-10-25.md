## 같은 날 후속 · 실제 임베딩과 검색 평가

- 사용자가 API 키 설정을 알린 뒤 기존 보류를 해제하고 실제 적재·검색 평가를 실행했다. 키 값은 출력하지 않았다. 제한 환경의 첫 시도는 APIConnectionError였으며 네트워크 제한 밖 재실행은 성공했다. 첫 오류를 인증 실패로 판단하지 않았다.
- 실제 Chroma 경로 data/runtime/chroma에 text-embedding-3-small 1,536차원 정책 11개를 적재했다. 테스트 인덱스와 분리했고 기존 오프라인 데이터를 삭제하지 않았다.
- 14개 양성 질문: 검색 상위 4개 Recall 평균 96.43%, 관련 조건 확장 후 100%. O08의 반품 조건 누락을 기존 관계 확장이 보완했다. 첫 검색 순위나 불필요한 후보의 정밀도까지 검증한 것은 아니다. [보고서와 한계](../evaluation.md#2026-10-25-실제-검색-평가)
- 성공한 실제 실행의 신규 벡터 25개, 백엔드 배치 15회. 금액/토큰 집계는 미수집이다. API 비활성 별도 프로세스 재실행에서 동일 결과, 신규 청크·벡터·백엔드 배치 모두 0을 확인했다.
- 다음: 고정 벡터 내보내기·복원과 에이전트/상담 연결. RAG 검색 기준선은 확보했지만 2일차 전체 완료는 아니다. 기본 RAG_ALLOW_API=false는 유지하므로 새 질문의 미캐시 임베딩은 자동으로 API 호출하지 않는다.
- Git: 동일 브랜치의 미커밋 변경으로 유지. 이번에 PR·push·병합은 하지 않았다.
- 후속 코드 검증: 평가 말뭉치 버전 대조를 추가하고 Recall all/any·빈 정답 거부 검사를 보강했다. 관련 pytest **7개 통과**, Ruff·git diff --check 통과. 기존 전체 테스트와 프런트 검사는 이번에 재실행하지 않았다.
