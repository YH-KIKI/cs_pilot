- 작업 기록 날짜: **2026-10-22** (사용자 지정 1일차 귀속일)
- 프로젝트 일차: 1일차. 자정 이후의 검수·문서 정리도 이 일차에 묶었다. 수집·검증 파일의 실제 타임스탬프와 Git 커밋 시각은 바꾸지 않았다.
- 상태: 1일차 범위 완료. 다음 기능은 RAG 적재·검색이다.

## 완료한 작업

- Python 3.12 가상환경·uv와 React + TypeScript + Vite 환경, 잠금 파일을 구성했다.
- SQLite orders/order_items 1:N, 고정 12주문·14품목, 초기화/검증 스크립트와 읽기 전용 SQL 조회를 구현했다.
- 상담 화면에서 가상 주문 조회를 연결했다. 품목별 상태·배송 날짜를 구분한다.
- Apple 한국 정책 3페이지를 수집하고 조건/예외를 보존한 11규칙 묶음을 정리했다.
- 고정 기준 시각의 평가 질문 24개와 기대 결과를 정의했다. 실제 검색/AI 평가 실행 결과는 아니다.
- Pydantic·Zod·OpenAPI 상담 계약과 6상태 예시를 작성했다. 실제 상담 실행은 501로 명시했다.
- Git 운영 규칙과 개발 기록 체계를 문서화했다. 기존 미커밋 구현은 아래 보존 커밋으로 남겼다.

진행 중/미구현: 청킹·임베딩·Chroma 정책 적재, 상담 LangGraph와 AI 결과 화면 연결. Chroma의 환경 점검용 벡터 검색만 수행했으며 정책 검색이 구현된 것은 아니다.

## 실제 검증과 결과

아래 구현 검사는 해당 작업을 수행할 때 실행한 결과다. 이번 개발 기록 문서화에서 기능 검사를 재실행한 것은 아니다.

| 실행한 검증 | 확인 결과 |
|---|---|
| pytest, ruff | 최종 21개 테스트 통과, 스타일 검사 통과. 초기 환경 단계는 11개였다 |
| React typecheck / check:contracts / build | 타입 검사·서버 예시의 Zod 계약 검사·프로덕션 빌드 통과 |
| SQLite 초기화·재실행·제약 검증 | 12주문/14품목, PK/FK·품목 매핑·읽기 전용·바인딩·재생성 일관성 확인 |
| validate_day1 | 3문서·11묶음의 출처/해시, 24사례의 주문·품목·날짜·도구 상한 정의 일치 |
| 실제 HTTP | UI·주문 API·Vite 프록시 확인. 상담 API는 의도한 501 확인 |
| Docker 빌드·실행·재시작 | 기본 환경 구축 시점의 이미지에서 UI/API·동일 주문 데이터 복원 확인. 이후 추가한 상담 계약으로 재빌드하지 않음 |
| 보존 커밋 전 검사 | 기존 75파일 내용 보존, 원본 스냅샷 7파일의 스테이징 바이트 대조, 제외 경로와 알려진 키 패턴 검사 통과 |

보존 커밋 전 전체 스테이징 공백 검사는 원본 HTML/TXT의 공백·줄바꿈 때문에 실패했다. 원문을 수정하지 않고 원본 폴더 밖의 공백 검사와 원본 해시 검증으로 구분해 통과시켰다. [원인과 처리](../decisions.md#t03).

이번 문서 마무리 검사: 로컬 Markdown 링크 41개와 문서 공백 검사, git diff --check를 통과했다. 체크포인트 이후 기존 파일 변경은 AGENTS.md·README.md의 기록 안내뿐이며 구현·데이터 내용이 보존됐음을 해시로 확인했다. 기능 테스트는 문서만 변경해 재실행하지 않았다.

미실행: 유료 OpenAI 호출, 실제 RAG 검색 정확도/에이전트 행동 평가, 브라우저 시각 검수, Render 배포, GitHub CI 실행. 기반 점검과 계약 예시 성공을 이들 기능의 성공으로 간주하지 않는다.

## 남은 문제와 다음 작업

- 다음 구현: 조건/예외 묶음을 유지한 청킹 → 임베딩 재사용 → Chroma 적재·출처 검색 → 검색 평가.
- 정책 수집일은 시행일이 아니다. 단순 기간 계산으로 최종 반품 승인이나 마감시각을 확정하지 않는다.
- 검색 품질과 상한/반복 흐름의 실제 동작은 아직 확인하지 않았다. 평가 전후 점수나 개선율도 없다.
- 보존 커밋은 리뷰·main 병합·원격 백업을 완료했다는 뜻이 아니다. 이후 기반 PR 검토와 별도 push가 남아 있다.
