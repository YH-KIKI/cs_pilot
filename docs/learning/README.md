# Python 학습 기록

AI를 활용한 개발을 유지하면서 실제 구현의 Python 문법과 데이터 흐름을 이해하기 위한 기록이다. 기능 구현과 필요한 검증을 마친 뒤 핵심 함수 1~2개만 짧게 설명한다. 프로젝트 전체 코드 해설이나 별도 수업 단계로 확대하지 않는다.

## 기록 구분과 날짜

| 기록 | 남길 내용 |
|---|---|
| [개발 일지](../devlog/README.md) | 완료/진행 중 작업, 실제 검증, 남은 문제, 커밋·PR |
| [주요 판단·문제 해결](../decisions.md) | 선택 이유·대안, 오류 원인·해결, 평가 개선 전후 |
| 학습 기록 | 핵심 함수의 Python 문법, 입력부터 반환까지의 흐름, 직접 풀 과제 |

기본 파일명은 학습 내용을 정리한 실제 날짜 기준 `YYYY-MM-DD.md`로 한다. 사용자가 과거 일차로 묶길 요청하면 지정한 귀속일을 파일명에 쓰되 실제 정리일을 본문에 별도로 적는다. 구현일·프로젝트 일차·학습 정리일을 혼동하지 않는다. 같은 날짜의 후속 내용은 같은 파일에 덧붙인다.

설명 대상의 현재 파일과 함수 이름을 확인하고 파일 링크를 남긴다. 가능하면 기준 커밋을 적고, 아직 커밋하지 않았다면 미커밋 코드임을 밝힌다. 이후 코드가 바뀌면 옛 설명을 현재 동작처럼 사용하지 않도록 갱신하거나 당시 버전을 표시한다.

## 한 번의 학습에 담을 내용

1. **범위:** 이번 기능에서 중요한 함수 1~2개. 선정 이유는 한 문장으로 충분하다.
2. **함수별 계약:** 파일 경로/함수명, 역할, 매개변수와 대표 값, 정상/실패 때의 반환값. 부수 효과가 있으면 함께 적는다.
3. **실행 흐름:** 입력 → 조건/반복/다른 함수 호출 → 데이터 변환 → 반환 순서로 설명한다. 실제 사용한 작은 값이 어떤 형태로 바뀌는지 보여준다. 예시를 실제 실행 결과로 표시하려면 직접 실행해야 한다.
4. **초급 문법:** 해당 코드에 등장하는 문법만 골라 설명한다. 예를 들어 def와 return, 타입 힌트, None, 리스트/딕셔너리, 반복·컴프리헨션, 조건 분기, 튜플, try/except/finally 등이 실제 데이터 처리에서 하는 일을 연결한다. 용어만 나열하지 않는다.
5. **호출과 예외:** 호출자 → 핵심 함수 → 하위 함수의 관계와 값 전달을 정리한다. 어떤 예외를 어디서 잡고 오류 값으로 바꾸는지, 어떤 예외가 상위로 전달되는지, 자원을 언제 닫는지 실제 코드 범위에서 구분한다. 예외 처리 코드가 없으면 없다고 적는다.
6. **수정 과제 1개:** 사용자가 직접 풀 수 있는 작은 변경을 제시한다. 대상 함수, 바꿔야 할 동작, 확인할 입력/기대 결과와 변경하지 않을 범위를 명확히 한다. 완성 코드·정답 diff·해설로 풀이를 먼저 노출하지 않는다.

확인한 동작, 읽은 코드로 설명한 흐름, 추정·미검증을 구분한다. 코드를 읽기만 했다면 실행했다고 쓰지 않는다. 라이브러리 내부 구현을 추측하거나 존재하지 않는 함수를 호출 관계에 넣지 않는다.

## 학습 과제와 개발 속도

- 과제는 학습 문서에만 제시하고 AI가 기능 코드·테스트를 먼저 수정해 풀어놓지 않는다. 사용자가 풀이/구현을 요청하기 전에는 미풀이로 둔다.
- 과제를 풀어야 다음 개발로 넘어갈 수 있다는 승인 단계는 만들지 않는다. 기존 개발과 검증을 먼저 마무리한다.
- 문서·설정 변경, Python 로직과 무관한 작업에는 새 기록을 억지로 만들지 않는다. 아직 설명할 기능이 없으면 빈 날짜 파일도 만들지 않는다.
- 개발 일지는 학습 문서 링크만, 기술 선택 이유는 decisions.md 링크만 연결해 긴 중복을 피한다.

## 현재 상태

사용자 요청으로 1일차 주문 조회를 학습할 로컬 `2026-10-22.md`를 작성했다. 실제 정리일은 2026-10-25이며 구현 코드와 과제의 정답은 수정하지 않았다.

## Git 제외 범위

날짜별 학습 파일과 exercises 등의 개인 연습 자료는 `.gitignore`로 제외한다. 이 README만 공통 운영 규칙으로 버전 관리한다. 이미 추적 중인 날짜별 학습 파일은 현재 없으며, force add하지 않는다. 학습 파일은 로컬에만 있으므로 clone·push에 포함되지 않는다. 원격 문서에서 해당 파일의 존재를 보장하지 않는다.

개발 일지·decisions.md·앱 코드·평가 자료는 기존대로 버전 관리한다. 개발 일지에는 필요하면 로컬 전용 경로와 학습 여부만 짧게 기록하고 함수 설명이나 과제 내용을 복사하지 않는다.
