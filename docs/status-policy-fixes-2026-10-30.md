# smoke 기준선 보존과 상태 정책 회귀 보강 · 2026-10-30

프로젝트 3일차 후속이다. 사용자 요청으로 [v6 검토](review-v6-2026-10-30.md)의 두 문제를 수정하고, 관련 실제 검증에서 드러난 구조화 상태/검색 필터 문제까지 보강했다. 기존 코드·문서·원본 보고서는 보존했다. Git 커밋/PR/병합은 이번 범위가 아니다.

## 1. smoke 보고서 보존

scripts/smoke_agent.py에 --output을 추가했다. docs 아래 새 JSON 파일만 허용하고 기존 파일은 **모델 호출 전에 거부**한다. 마지막 저장은 Path.open('x')를 사용해 초기 검사 후 다른 실행이 같은 파일을 만들었어도 덮어쓰지 않는다. 기존 day3-agent-smoke.json은 수정하지 않았다. 기존 결과를 강제로 덮어쓰는 옵션은 추가하지 않았다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.smoke_agent --allow-api --case O08 --output docs/new-o08-smoke.json
```

예시 경로가 이미 있다면 새 이름을 사용한다. 기본 경로의 기준선이 이미 있으므로 --output 없이 재실행하면 거부한다.

수정 전 임시 기준선/모델 대역으로 새 검사 3개 실패를 확인했고, 수정 후 새 6개가 통과했다. 기존 기본/명시 출력 거부·새 출력 저장·경로/확장자 거부·실행 중 다른 작성자의 파일 보존을 검사했다. 실제 기준선 바이트와 첫 P01 사례를 유지했다. 이 검사들은 실제 API를 호출하지 않는다.

## 2. P02: 상태 이름과 허용 행위를 구분

v6 P02는 실제 인용 원문과 달리 주문 접수에서도 변경 가능이라고 설명했다. v7 지침에서 주문 접수는 아직 변경 불가, 주문 처리 중은 변경 가능이라고 명시하고 변경과 취소를 각 정책 문구로 설명하게 했다. 상태 라벨을 아는 것만으로 행위 허용을 추론하지 않는다.

기존 24개 질문/정답을 바꾸지 않고, 상태 차이를 직접 묻는 SP01을 [별도 보충 자료](../data/eval/status_policy_cases.json)에 추가했다. P02에서 문제 문장을 단순히 생략하는 것과 구분하기 위한 질문이다. SP는 이 프로젝트의 status-policy 추가 사례 접두어다. 실제 주문 변경을 실행하는 기능은 추가하지 않았다.

## 3. 관련 검증에서 드러난 문제와 보강

| 사례 | v7 최초 관련 평가 | 후속 보강 및 v8 확인 |
|---|---|---|
| P02 | 두 상태의 변경 가능 여부는 올바르게 설명 | 재검증에서도 접수 불가/처리 중 가능을 설명 |
| O03 | 결론·근거는 있지만 needs_information + 빈 missing_fields를 제안해 system_error | 남은 모델 판단 안에서 구조 일관성을 보완하도록 feedback. 계속 틀리면 오류 종료하며 상태/질문/초안을 서버가 만들지 않음 |
| SP01 | 주문 상태 문서는 cancellation인데 shipping 필터를 두 번 선택해 근거 제외 | 실제 정책 분류와 topic=null 전체 검색 선택지를 지침에 명시. v8은 cancellation 검색으로 실제 근거를 찾아 차이를 설명 |

O03의 실제 실패 제안을 고정 재생한 검사 2개가 수정 전 실패했다. 보완 후 정상 재판단과 반복 오류의 한도 종료를 확인했다. 모델 4회·조회 1회·검색 2회·전체 도구 3회 상한과 잘못된 인용 검증은 유지했다.

v8 실제 O03은 처음부터 정상 answered/초안을 내서 feedback 경로는 필요하지 않았다. 그 경로 자체는 고정 재생 테스트로 검증했다. SP01도 처음부터 cancellation을 선택해 topic=null 재검색은 실제로 사용하지 않았다. 선택지 추가와 실제 실행한 경로를 구분한다.
