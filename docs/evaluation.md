## 세 단계로 검증

1. **1일차 정의 검증:** 질문 스키마, 주문·품목 존재, 기대 정책 ID, 도구 상한, 날짜 차이, 출처·해시를 검사한다. 현재 완료 대상이다.
2. **2일차 검색 평가:** 기대 정책 묶음이 top-4 결과에 포함되는지 측정한다. 모든 기대 묶음이 필요한 기본 `all`과 대체 근거가 가능한 `any`를 구분한다. 관련 묶음 확장을 포함한 검색 결과로 평가하며 Recall@4 목표는 90% 이상이다. 불필요하게 중복된 묶음은 한 번만 센다.
3. **에이전트 통합 평가:** 상태·도구 선택/횟수·추가 확인 항목·출처·must_include/must_not_include를 확인한다. 문장 완전 일치를 요구하지 않는다. 정책의 실제 적용 의미는 사람이 결과를 읽고 검토한다.

`mode=integration`은 실제 검색·에이전트에 사용할 정의다. `mode=mocked_tools`는 검색 결과/오류/반복 요구를 고정해 흐름을 재현하는 정의다. 현재는 에이전트가 없어 두 모드 모두 행동 평가를 실행하지 않았다.

R01은 첫 검색에 order-status만, 두 번째에 order-cancellation을 반환하는 모의 도구로 검사한다. R02는 첫 결과부터 충분하다. 실제 검색에서는 처음부터 충분하면 재검색하지 않아도 성공이며, 의미 없는 재검색을 강제하지 않는다.

호출 상한 위반·존재하지 않는 인용·주문 사실 조작은 평가 세트에서 0건을 요구한다. `must_include`는 의미 기준 체크리스트이며 현재 문자열 매칭 점수나 LLM 평가 점수를 산출하지 않았다. 평가 결과를 추가할 때 실행 모델·프롬프트·말뭉치·시드 버전·토큰 비용을 함께 기록한다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.validate_day1
```

검증 결과는 `docs/day1-validation.json`에 기록한다. 검색 정확도와 에이전트 행동은 `not_run`으로 남겨 정의 검증 성공과 구분한다.

## 2026-10-25 실제 검색 평가

[검색 보고서](retrieval-evaluation.json): OpenAI text-embedding-3-small, 1,536차원, 정책 11개를 적재했다. 24개 정의 중 integration이면서 기대 정책이 있는 14개만 검색 Recall 평가에 사용했다. 모의 도구·오류·근거 없음 사례를 성공 분모에 넣지 않았다.

- 질문별 Recall 평균: 검색 상위 4개 96.43%, 관련 조건 확장 후 100%. 모든 기대 조건을 충족한 질문은 각각 13/14, 14/14였다. P04는 사전에 정의한 any 기준이다.
- O08에서 returns-standard가 상위 4개에 없었다. 기존 returns-process → returns-standard 연결로 보충됐다. 확장 결과는 5개가 될 수 있으므로 확장 후 수치를 엄밀한 순수 top-4 성능과 혼동하지 않는다. 평가 보고서의 expanded_recall_at_4는 top-4를 출발점으로 확장한 결과를 뜻한다.
- P03은 필요한 규칙이 포함됐지만 첫 순위는 returns-damage였다. 따라서 이 결과는 검색 순위·정밀도 또는 답변 품질이 모두 충분하다는 뜻이 아니다. 작은 고정 질문 세트의 최초 기준선이다.
- API 비활성 재실행에서 동일 결과와 신규 벡터/백엔드 호출 0회를 확인했다. 첫 성공 실행은 정책 11개 + 질문 14개 = 신규 벡터 25개, 백엔드 배치 호출 15회였다. 실제 사용 토큰·청구 비용은 수집하지 않아 금액을 확정하지 않는다.
- 에이전트 행동·날짜 판단·근거 없는 답변 방지·답변 생성은 미실행이다. 기존 day1-validation.json은 당시 정의 검증 보고서로 보존한다.

## 2026-10-30 기본 상담 연결 검증

## 알려진 문제 · 조사 변경에 대한 결과 민감도

- 2026-10-30 사용자가 화면에서 단어 뒤 조사 하나 차이로 결과가 달라지는 현상을 관찰했다. 현재는 **사용자 보고, 재현·원인 미확인**이다. 정확한 질문 쌍과 당시 주문/품목·출처·실행 내역은 아직 확보하지 않았다.
- 사용자 요청에 따라 지금은 기록만 하고 조회 방향·검색어·프롬프트·답변 로직을 수정하지 않는다. 단순 표현 차이인지 의미 차이인지도 구체적 입력을 확보한 뒤 판단한다.
- 후속 재현 시 같은 주문/품목·기준일·인덱스/모델/프롬프트 조건으로 두 문장을 비교하고, 선택 행동·검색어·검색 후보/적용 근거·최종 상태/답변 중 어디서 달라지는지 분리해서 기록한다. 모델의 확률적 변동과 문장 차이의 영향도 구분한다. 아직 개선 전후 수치나 회귀 통과 기록은 없다.
