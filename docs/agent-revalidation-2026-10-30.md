# 전체 재검증과 R02 상태 의미 보강 · 2026-10-30

프로젝트 3일차 후속이다. 사용자 요청에 따라 먼저 P03 수정본(v4)으로 고정 24사례를 재검증하고, 실제 결과를 확인한 뒤 R02 상태 의미와 재발한 O08 확인 항목을 보강했다. 수정 후 v5로 같은 24사례 전체를 한 번 더 실행했다. 유리한 결과만 선택하거나 질문/기대 정답을 변경하지 않았다.

## 발견과 변경

- R02는 v4에서도 구조 검사를 통과했으나 “processing이 출고 준비 중인지 확인할 수 없다”고 설명했다. 화면에는 프로젝트의 한국어 상태 매핑이 있지만 모델에는 코드 의미가 명시되지 않았다. v5는 모델 입력에 실제 품목별 코드·한국어 표시·확인 여부·snapshot_at을 전달한다. processing과 preparing/shipped의 차이를 알려주되 취소 조건이나 실행 결과를 대신 확정하지 않는다.
- v5 R02는 두 품목의 주문 처리 중 상태와 기록 시각을 설명하고 Visa 다품목 단일 취소 예외를 안내했다. v4의 번역 미확인 혼선은 이번 출력에서 나타나지 않았다. 검색은 두 실행 모두 1회이며 추가 번역 검색은 없었다.
- O08 v4는 14일 계산·마감시각 확인 권고 문장은 맞았지만 missing_fields=[]와 insufficient_evidence를 반환했다. 기존 서버 보정은 확인 항목이 있어야 작동하므로 적용되지 않았다. v5는 이런 마감시각 문의에서 needs_information과 other의 구체적인 확인 질문을 함께 내도록 지침을 명확히 했다.
- O08 v5는 14일 계산을 유지하고 other 질문을 포함해 needs_information으로 종료했다. 이 보완은 모델 지침이며 서버가 자유 문장에서 질문을 추출하거나 임의 질문을 생성하는 규칙은 추가하지 않았다. 다른 출력에서도 항상 일관된다는 보장은 아니다.
- P03은 두 전체 실행 모두 두 기한과 조건·예외를 설명·인용했다. O09의 15일 기간 경과, F01의 shipped 사실 보존, 없는 주문·오류·상한 경로도 v5 구조 검사를 통과했다.

## 실제 검증과 비용 기록

- 상태 사실 전달을 검증하는 새 3개 테스트는 수정 전 필드 누락(KeyError)으로 실패했고 수정 후 통과했다. 이것은 모델 입력 계약의 회귀 검사이며 잘못된 자연어 전체를 결정적으로 재생/판정한 테스트라고 주장하지 않는다.
- 전체 pytest **80개 통과**, Ruff 통과. known processing과 품목별 preparing/unknown 구분, 사용자 조작 문장에도 shipped 사실 유지, 미조회/없는 주문의 빈 상태 사실, 원본 조회 객체 비변경을 검사했다. 7개 상태 라벨의 enum 전체 포함과 기존 UI 표시 일치도 별도 Python 검사로 확인했다.
- React TypeScript typecheck·check:contracts 통과. 실제 v4/v5 공개 응답 **48개 모두 Zod 검증 통과**. UI/공개 API 계약/SQL/고정 데이터/의존성은 변경하지 않았다. 프런트 빌드·브라우저 클릭·배포는 재실행하지 않았다.
- v4 모델 **54회**, 입력 123,610·출력 10,862·총 **134,472토큰**.
- v5 모델 **55회**, 입력 142,667·출력 11,037·총 **153,704토큰**.
- 이번 두 전체 평가 합계 **109회·288,176토큰**. 앞선 P03/O08 부분 평가나 이전 일차 사용량은 포함하지 않는다. 질문 임베딩 토큰·실제 청구액·잔액은 미집계다. .env/키는 수정·출력하지 않고 평가 프로세스에서만 API를 허용했다.

## 수동 검토에서 남은 문제

- **P01:** v5의 “유료인가요?”에 “네. ... 무료입니다”로 시작해 첫 표현의 극성이 모호하다. 무료라는 핵심 사실은 맞지만 문장 수정 대상으로 남긴다.
- **P04:** 파손 문의의 공식 상담 경로는 맞지만, 요청하지 않은 일반 반품의 최초 상태 요건을 길게 붙여 파손에도 똑같이 적용하는 것처럼 읽힐 여지가 있다. 또한 보안 기능의 활성화와 비활성화 불가라는 결합 조건을 단순 활성화로 축약한 문장이 있어 거부 조건이 넓어졌다. 인용 ID와 원문 보존만으로 요약의 조건 누락을 막지 못한다.
- **O05/O07:** 단일 품목의 불필요한 재확인과 실제 승인/실행이 아니라는 초안 표현을 더 명확히 할 여지가 있다. v5에서 환불 실행 완료를 주장한 것은 아니다.
- v4 O10에는 Apple 브랜드 한정이 빠진 소프트웨어 사용권 예외 설명이 있었다. v5에서는 해당 부가 설명이 나오지 않았지만, 별도의 예외 질의 전체를 검증한 것은 아니다. 이전 문제를 삭제하지 않는다.
- 조사 하나 차이의 민감도는 사용자 요청대로 계속 보류했다. 정확한 질문 쌍 재현이나 조사 전처리는 하지 않았다.

다음 추천은 **P04의 질문과 무관한 조건 부착 및 원문의 결합 조건 누락을 우선 수정·부분 검증**하는 것이다. P01의 응답 극성도 함께 확인한 뒤 LangGraph 핵심 PR을 정리한다. 구조 24/24만으로 의미 품질/실제 배포 준비 완료를 선언하지 않는다.

Git은 codex/feat-consultation-graph, 기준 보존 커밋 4c9b681 이후 미커밋이다. 이번 요청에서 커밋·push·PR·main 병합은 실행하지 않았다. 기존 개발 서버는 재시작하지 않아 새 수정본이 자동 반영됐다고 보지 않는다.
