# 정책 수집·검수 기록

검수일: 2026-10-23 (Asia/Seoul). 말뭉치: `apple-kr-20261023-v1`.
검수는 Codex가 원문과 추출 결과를 대조한 기록이며 회사 정책 담당자의 승인이나 법률 검토가 아니다.

## 수집 결과

| 문서 | 원문 | 보존한 규칙 묶음 |
|---|---|---|
| 주문 확인 및 변경 | https://www.apple.com/kr/shop/help/viewing_changing_orders | 주문 상태, 배송 추적, 주문 취소 |
| 배송 및 픽업 | https://www.apple.com/kr/shop/help/shipping_delivery | 표준 배송, 예상 일정, 맞춤 구성, 도착 시간, 누락·손상 |
| 반품 및 환불 | https://www.apple.com/kr/shop/help/returns_refund | 반품 절차, 표준 반품 약관, 결함·손상 |

원본 HTML 3개를 HTTP 200으로 수집했다. `data/policies/manifest.json`에 문서 제목·URL·실제 수집 시각·원본 SHA-256을 보관했다. UTC 수집 시각은 서울 기준 2026-10-23이다. 원문에 명시된 시행일을 확인하지 못했으므로 `effective_date`는 모두 null이다. 수집일을 시행일로 취급하지 않는다.

`raw`는 감사·대조용 원본이며 메뉴·푸터도 포함한다. `curated/rule_groups.json`의 11개 묶음이 2일차 RAG 입력이다. 문서별 Markdown은 읽기용이다. 임베딩에는 공식 `text`와 제목·섹션 경로를 사용하고, 개발자의 `review_summary`를 공식 근거로 인용하거나 Markdown 전체를 그대로 넣지 않는다. 아직 청킹·임베딩·벡터DB 적재는 하지 않았다.

## 조건과 예외 검수

| 묶음 | 대조한 내용 | 답변 시 주의 |
|---|---|---|
| order-status | 품목별 상태 의미 | 주문 ‘변경’과 ‘취소’를 같은 행위로 취급하지 않음 |
| order-cancellation | 출고 준비/출고됨 제한 + 카드 3종의 다품목 부분 취소 예외 | 상태만 검색하고 카드 예외를 누락하지 않음 |
| order-tracking | 품목별 추적 정보 | 가상 스냅샷을 실시간 위치로 표현하지 않음 |
| shipping-options | 표준 배송 무료와 주문별 옵션 | 다른 배송 옵션까지 무조건 무료라고 확대하지 않음 |
| shipping-estimates | 예상 일정과 변경 가능성 | 도착 보장·정확한 시각 생성 금지 |
| shipping-customized | 각인·맞춤 구성 준비 시간 | 실제 주문 근거 없이 지연 원인으로 확정하지 않음 |
| shipping-eta | 정확한 도착 시간 확인 제한과 지역별 안내 | 지역 등 정보가 없으면 특정 시간대 약속 금지 |
| shipping-damage / returns-damage | 누락·손상 시 공식 상담 방향 | 자동 환불·정액 보상으로 확대하지 않음 |
| returns-process | 수령 후 시작 기한, 신청 후 센터 도착 기한, ZEISS 예외 | 두 기한을 분리해서 안내하고 표준 반품 조건도 함께 확인 |
| returns-standard | 영수증·최초 상태·구성품·국가·상품 제외·보안 기능 | 기간만으로 최종 승인을 단정하지 않음 |

`returns-process`는 `related_rule_groups`로 `returns-standard`를 연결했다. 2일차 검색 도구에서 관련 조건 묶음도 함께 반환한다. 긴 조건 묶음을 하위 청크로 나누더라도 부모 묶음을 복원한다.

## 발견한 주의점과 범위 결정

1. 반품 약관은 HTML 내 오버레이에도 들어 있다. 화면 본문만 추출하면 제외 조건을 놓칠 수 있어 `표준 반품 정책` 오버레이를 수집했다.
2. 동일 약관이 주문 페이지에도 포함된다. 반품 약관의 정식 검색 대상은 반품 페이지의 하나로 통일하고 중복 임베딩하지 않는다. 다른 원문 스냅샷은 보존한다.
3. 상태 설명과 주문 변경 섹션에 주문 접수 상태의 변경 가능성 표현 차이가 있다. 이번 범위에서는 취소 섹션을 근거로 삼고 변경 기능은 다루지 않는다.
4. 취소 섹션의 부정 조건을 배송 완료·취소됨·unknown에 기계적으로 적용하지 않는다. 적용 범위가 불명확하면 확인을 요청한다.
5. 보안 기능은 단순히 ‘켜져 있음’만으로 일괄 반품 불가가 아니다. 비활성화 가능 여부의 조건까지 보존했다.
6. 반품 문서의 일부 상품·은행 정보 등에는 오래된 표현이 있을 수 있다. 게시·시행일을 추정하거나 최신 법률 전체로 표현하지 않는다. 범위를 벗어난 내용은 상담원 확인으로 보낸다.
7. 픽업·해외 구매 상세·보증·가격 보호·업무일 환불 예정일 계산은 제외한다. 소프트웨어는 일반 반품의 제외 조건을 안내하는 데까지만 사용한다.
8. 수령 후 14일의 구체적 마감시각은 생성하지 않는다. 고정 기준일의 날짜 차이는 재현 가능한 보조 정보로만 사용한다.
9. 정책은 실제 공개 자료이고 주문은 가상 데이터다. 평가 기준일은 2026-10-22, 수집일은 서울 기준 2026-10-23이다. 이 날짜 차이는 과거 시행 여부의 검증을 뜻하지 않으며, 고정 스냅샷을 사용하는 학습 평가다.

## 재현과 검증

기존 원문을 다시 내려받지 않고 정리 결과를 재생성할 수 있다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.curate_policies
.\.venv\Scripts\python.exe -X utf8 -m scripts.validate_day1
```

다시 수집할 때는 `collect_policies --version 새버전`으로 명시적으로 실행하고 `selection.json`과 검수 기록을 갱신한다. 자동 갱신 기능은 없다. 원문은 바이트 그대로 보존하고 정리 JSON은 LF로 저장해 Git 체크아웃 후에도 해시 검증이 재현되게 했다.
