# O03 후속 · 정책 안내와 실행 동의의 구분

실제 작업일 2026-10-31, 프로젝트 3일차 후속. 기준 커밋은 `e6c42bf`다. 이번 단위는 O03 보강·관련 부분 평가·보존이며 전체 평가와 병합은 포함하지 않는다.

## 실패와 변경

v8 전체 평가의 O03은 A03의 Visa 결제·두 품목·대상 01·처리 중 상태와 부분 취소 제한 근거를 확보했지만, 모델이 “전체 주문 취소로 변경할 의사”를 `other` 확인 항목으로 만들고 `needs_information`으로 끝났다. 취소 실행을 하지 않는 상담 서비스에서 제한과 대안을 설명하는 데 그 의사 확인이 필수는 아니었다. 이전의 “질문 없는 needs_information”과 달리 유효한 질문이 있어 기존 구조 보완을 통과했다.

- 프롬프트 **v9**는 정책 안내와 실행 동의를 구분한다. 제한과 대안을 설명하되 실제 동의를 추정하거나 처리를 실행하지 않는다. 전체 프롬프트 정리는 하지 않았다.
- `needs_partial_cancellation_reconsideration`은 조회한 제한 카드(Visa/MasterCard/Diners)·다품목·선택 품목·실제 적용한 검수 취소 근거가 확인되고, 확인 항목이 `other`뿐인 경우 재검토 대상으로 판단한다. 인용 ID의 유효성도 확인한다. 검색 후보에 취소 정책이 있기만 한 경우는 제외한다.
- `decide`는 남은 모델 판단 횟수 안에서 재판단 피드백을 전달한다. 동의만 미확인이라면 안내를 작성하고, 다른 판단 사실이나 근거가 실제로 부족하면 질문을 유지하도록 한다.
- 서버가 상태를 `answered`로 바꾸거나 동의를 생성하지 않는다. 모델이 계속 질문을 내면 기존 질문을 보존한 `needs_information`으로 종료한다. 카드/상태 등의 실제 누락 필드·미선택 품목·다른 정책/손상 검수본·잘못된 인용을 이 경로로 덮지 않는다.
- 모델 4회·도구 3회·조회 1회·검색 2회와 공개 계약은 유지한다. 피드백으로 모델 호출이 늘 수 있지만 기존 판단 상한 내에서만 실행한다. 추가 검색을 자동 실행하지 않는다.

## 실제 검증

수정 전 저장된 O03 제안을 재생하는 새 검사 2개가 실패했다. 수정 후 새 검사 **14개** 포함 전체 pytest **128개**, Ruff 통과. 과거 제안에 보완 모델 제안을 덧붙이면 네 번째 판단에서 답변하고 도구는 조회/검색 각 1회다. 같은 질문을 반복하면 네 번째 판단 안에서 초안 없이 질문을 유지한다. 실제 누락 사실·모르는 카드/현금성 결제·후보만 검색·검수본 불일치·잘못된 인용·대상 미선택도 확인했다.

[새 부분 원본](o03-verification-2026-10-31.json): **O03/R02/O08/F01 4/4 구조 통과**. 실제 LLM은 네 사례 모두 사용했다. O03/O08/F01은 실제 SQLite/Chroma이며 R02는 실제 SQLite와 고정 모의 검색이다. 기준일은 기존 `2026-10-22T12:00:00+09:00`이고 기존 24개 질문/정답은 변경하지 않았다.

실제 O03은 처음부터 정상 답변해 **3회 판단**, 피드백 분기는 사용하지 않았다. 네 번째 판단의 보완 경로는 고정 재생 검사로 확인했으며 실제 API가 그 경로를 사용했다고 표현하지 않는다. 실제 네 사례는 각각 조회/검색 1회씩, 모델 판단 3회씩이었다.

- 응답 네 개를 읽어 검토했고 Zod **4개**, `npm run check:contracts` 통과. 새 보고서의 상담 소스 해시와 현재 코드를 대조했다.
- 실제 모델 **12회·39,047토큰**(입력 36,676·출력 2,371). 임베딩 토큰·청구액/잔액은 미집계다. API 허용은 평가 프로세스에 적용했으며 `.env`는 수정하지 않았다.
- 전체 24개·UI 클릭·TypeScript typecheck/build·Docker/원격 배포는 미실행이다. 이전 전체 23/24를 새 점수로 바꾸지 않는다. 이 보강으로 모든 불필요한 질문이나 모든 문장 의미 문제가 해결됐다고 일반화하지 않는다.
- 기존 자체 8000 서버를 v9로 재시작하고 health HTTP 200을 확인했다. 서버 API 허용은 프로세스에만 적용하고 `.env`는 유지했다. 이 확인은 브라우저 클릭 검증을 대신하지 않는다.
