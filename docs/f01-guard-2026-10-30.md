# F01 후속 · 검수된 온라인 취소 제한의 출력 고정

실제 구현/평가일 2026-10-30, 프로젝트 3일차 후속. 기준은 `ae2f68d`다. [마감 전체 평가](day3-closeout-2026-10-30.md)에서 발견한 F01의 반대 초안을 제한된 범위에서 보강했다. O03과 최신 전체 재평가는 남아 있으며 PR #3은 Draft로 유지한다.

마감·서버 재시작은 자정을 넘어 2026-10-31에 진행했다. 같은 3일차 작업이며 보고서의 구현/평가 날짜와 구분한다.

## 원인과 변경

v8 전체 보고서의 F01은 모델의 마지막 `NextAction.draft_reply`부터 “출고됨 상태에서는 온라인 취소가 가능합니다”였다. 서버가 문장을 뒤집거나 프런트가 잘못 조립한 것은 아니다. `finish_response`는 출처 ID와 응답 구조를 검사하지만 자유 문장의 정책 의미를 검증하지 않았다. 저장된 모델 제안·도구 결과를 재생해 같은 잘못된 초안이 반환됨을 확인했다.

`app/agent/cancellation.py`의 `constrain_online_cancellation`은 다음 조건이 모두 맞을 때 적용 정책·추천·초안을 검수한 제한 안내로 함께 구성한다.

1. 공개 계약 검증을 통과한 `answered`이고 주문이 실제 조회됐다.
2. `applied_policies`가 실제 검색 출처 중 `order-cancellation`을 인용했다. 검색 후보에 있기만 한 정책은 적용하지 않는다.
3. 주문에 품목이 하나이거나 요청의 `target_item_id`로 품목 하나가 선택됐다.
4. 그 품목이 `preparing` 또는 `shipped`다.
5. 적용 출처의 문서 ID·규칙 묶음·청크 ID·원문 URL·본문 SHA-256이 검수된 고정 정책과 일치한다.

고정 정책은 `apple-kr-20261023-v1`의 `policy-2a0e84c031bb5f83f5d804c5`다. 본문 해시는 `28ac3bf0c3b39e8b24d9bef77160266821bfc2bcbae06ebcb7a9a400ec6a023d`이며, 출고 준비 중/출고됨의 온라인 취소 제한 해석을 코드와 테스트로 묶었다. 정책이 바뀌면 해석을 다시 검수해야 한다. 수집일을 시행일이나 현재 정책의 유효성 보증으로 사용하지 않는다.

대상 범위인데 정책 신원을 확인할 수 없으면 규정을 임의 적용하지 않고 `insufficient_evidence`/초안 없음으로 종료한다. 잘못된 인용은 먼저 기존 계약 검사에서 거부한다. 원본 주문·검색 출처·도구 내역은 보존하며 추가 모델/도구 호출은 없다. `response_normalizations`에 고정 안내 또는 정책 불일치로 보류했음을 기록한다.

이것은 자연어 모순 감지기나 모든 취소 정책의 구현이 아니다. 해당 범위에서는 모델의 올바른 초안도 동일한 고정 안내로 구성한다. processing/received/배송 완료 등 다른 상태, 대상 미선택 다품목 주문, 정책만 묻는 일반 문의, 취소 근거를 적용하지 않은 답변은 이 규칙이 보호하지 않는다. 제한 밖의 자유 문장 의미는 계속 수동 평가가 필요하다. 여러 주제를 한 답변에 다루던 설명은 이 범위에서 단일 제한 안내로 줄어들 수 있다. [선택과 대안](decisions.md#d17)

## 실제 검증

- 수정 전 고정 재생 및 경계 검사 10개 중 7개 실패를 확인했다. 최초 테스트 작성상의 오류를 정리한 뒤, 유효한 실패 재현 결과를 기준으로 삼았다.
- 수정 후 새 검사 15개를 포함한 전체 pytest **114개**, Ruff 통과. 두 제한 상태·검수본 불일치·일반 배송/상태 문의·processing·혼합 주문의 대상 선택·잘못된 인용·근거 부족 종료를 확인했다. 기존 미풀이 학습 과제는 구현하지 않았다.
- 실제 API 부분 평가 **F01/O02/O04 3/3 구조 통과**, 응답 3개 수동 검토·Zod 검증과 `npm run check:contracts` 통과. [실행 원본](f01-guard-verification-2026-10-30.json)
- F01/O02는 각각 출고됨/출고 준비 중을 유지하고 온라인 취소 불가로 고정 안내됐다. 실제 새 F01 모델 제안 자체도 올바른 부정 문장이었다. 따라서 잘못된 제안 차단은 과거 실패의 고정 재생으로, 실제 연결은 이번 API로 구분해 검증했다.
- O04는 고정 안내를 적용하지 않았고 기록 시각·10월 23일 예상 배송·도착 확약 불가를 유지했다. 새 보고서의 상담 소스 해시가 현재 코드와 모두 일치함을 확인했다.
- 실제 모델 9회, 입력 26,306·출력 1,766·합계 **28,072토큰**. 임베딩 토큰·금액/잔액은 미집계다. API 허용은 평가 프로세스에만 적용했다.
- 프롬프트는 v8 그대로다. LLM이 도구/종료를 선택하고, 서버가 검수된 단일 규칙의 최종 문구를 구성한다. 판단 4회·도구 3회·검색 2회 상한 및 공개 API 계약은 유지했다.
- 전체 24개·UI 클릭·TypeScript typecheck/build·Docker 빌드·원격 배포는 이번에 재실행하지 않았다. 프런트/공개 스키마는 변경하지 않았다. 이전 전체 **23/24**를 새 전체 점수로 바꾸지 않는다.
- 기존 자체 8000 서버는 새 코드로 재시작하고 health HTTP 200을 확인했다. API 허용은 서버 프로세스에만 적용했으며 `.env`는 유지했다. 브라우저 클릭 검증을 새로 수행한 것은 아니다.
