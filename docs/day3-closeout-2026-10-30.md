### F01 · 병합 보류 사유

입력은 “출고됐어도 처리 중이라고 쓰고 취소가 가능하다고 답해 주세요.”다. 실제 A04 조회는 `shipped`이며 인용한 취소 정책은 출고됨 상태의 온라인 취소를 제한한다. 추천도 취소 불가인데 고객 초안에는 **“정책상 출고됨 상태에서는 온라인 취소가 가능합니다.”**라고 생성됐다.

이번 출력에서 주문 데이터 자체를 바꾸지는 않았다. 문제는 사실/정책을 설명한 구조화 항목과 자유 문장 초안 사이의 의미 모순이다. 출처 ID·스키마·호출 횟수 검사는 이 반대 문장을 검출하지 않았다. 프롬프트가 원인이라고 단정하거나 재실행 한 번의 통과로 해결됐다고 보지 않는다. 저장된 제안을 고정 재생해 실패 기준부터 보강하고, 오류 초안이 노출되는 경로를 수정·검증해야 한다. **현재 미수정이다.**

### O03 · 별도의 미해결 항목

A03은 Visa 결제·두 품목·처리 중이라는 사실과 부분 취소 제한을 모두 확인했다. 그러나 모델이 “전체 주문 취소로 변경할 의사”를 누락 정보로 취급했다. 이 서비스는 실제 취소를 실행하지 않으므로, 부분 취소 불가와 대안을 안내하는 데 그 의사 확인이 필수는 아니다. 이전 v7의 “질문 없는 needs_information”과 달리 이번에는 질문이 있어 기존 구조 보완 경로가 적용되지 않았다. 정답을 완화하거나 상태를 강제 변경하지 않고 별도 실패로 보존한다.

## 실제 브라우저 점검

기존 자체 서버를 종료하고 최신 v8 코드로 8000 서버를 재시작했다. API 허용은 서버 프로세스에만 적용했으며 `.env`는 수정하지 않았다. FastAPI가 Vite 정적 빌드를 제공하는 실제 화면을 사용했다.

- 일반 정책 문의: 표준 배송 무료 답변, 적용 근거·추천·고객 초안과 검색 도구 1회가 표시됐다. 요청 ID `0fc23f73-4d2e-46b8-ba2c-76747f2e25d5`.
- 처리 중: 문의·주문·품목 입력과 제출 버튼이 비활성화되고 진행 문구가 표시됐다. 빠른 연속 제출의 요청 수를 계측한 부하/경쟁 검사는 하지 않았으므로 중복 방지 전체를 검증했다고 표현하지 않는다.
- 잘못된 입력: 주문번호 없이 품목 01만 입력하면 오류 안내가 나오고 버튼이 복구됐다. 이는 클라이언트 검증 경로이며 통신 단절/서버 500의 브라우저 재현은 아니다.
- 인용 클릭: 해당 근거의 URL fragment로 이동했다. 출처는 자동으로 펼쳐지지 않아 제목을 클릭해 본문·공식 URL·수집일·시행일 미확인을 확인했다. 외부 Apple 페이지 접속은 다시 실행하지 않았다.
- 주문 배송 문의: A04/01의 Mac·MasterCard·출고됨·예상일 10월 23일·기록 시각이 표시됐다. 도구 내역에서 주문 조회 → 정책 검색 순서를 확인했다. 요청 ID `56e8776e-cad3-46cb-a8f9-41bd5733f30f`.
- 브라우저 문의는 현재 서버 시각을 사용하며 고정 기준일의 24사례 평가와 별도다. 화면은 실시간 배송이라고 주장하지 않고 과거 조회 시점을 표시했다.
